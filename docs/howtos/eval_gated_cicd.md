# Eval-Gated CI/CD with RAGAS

This guide shows how to block deployments automatically when
retrieval quality drops below a threshold using RAGAS and
GitHub Actions.

## Why this matters

Most RAG pipelines are deployed manually after eyeballing
outputs. Eval-gated CI/CD treats quality as a hard gate —
if faithfulness drops, the pipeline blocks the merge before
anything reaches production.

## Prerequisites

- A working RAG pipeline
- RAGAS installed: `pip install ragas`
- A dataset of questions and expected answers for evaluation

## 1. Write the evaluation script

Create `scripts/evaluate_rag.py` in your project:

```python
import sys
from datasets import Dataset
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy

# Replace with your actual RAG pipeline output
# Each entry: question, answer generated by your RAG, and the
# source contexts your retriever returned
samples = [
    {
        "question": "What is the statute of limitations for contract disputes?",
        "answer": "The statute of limitations for contract disputes is typically 6 years.",
        "contexts": ["Under common law, contract disputes must be filed within 6 years of the breach."],
        "ground_truth": "6 years under common law for contract disputes."
    },
    # Add your full evaluation dataset here
]

dataset = Dataset.from_list(samples)

results = evaluate(
    dataset=dataset,
    metrics=[faithfulness, answer_relevancy],
)

print(f"Faithfulness:      {results['faithfulness']:.4f}")
print(f"Answer Relevancy:  {results['answer_relevancy']:.4f}")

# Set your thresholds here
FAITHFULNESS_THRESHOLD = 0.85
RELEVANCY_THRESHOLD = 0.80

failed = False

if results["faithfulness"] < FAITHFULNESS_THRESHOLD:
    print(f"FAIL: Faithfulness {results['faithfulness']:.4f} is below threshold {FAITHFULNESS_THRESHOLD}")
    failed = True

if results["answer_relevancy"] < RELEVANCY_THRESHOLD:
    print(f"FAIL: Answer relevancy {results['answer_relevancy']:.4f} is below threshold {RELEVANCY_THRESHOLD}")
    failed = True

if failed:
    sys.exit(1)  # Non-zero exit code fails the CI job

print("PASS: All metrics above threshold. Safe to deploy.")
sys.exit(0)
```

## 2. Add the GitHub Actions workflow

Create `.github/workflows/eval_gate.yml` in your project:

```yaml
name: RAG Evaluation Gate

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  evaluate:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install dependencies
        run: |
          pip install ragas datasets openai langchain

      - name: Run RAGAS evaluation
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        run: |
          python scripts/evaluate_rag.py

      # This step only runs if the previous step passes (exit code 0)
      - name: Deploy
        if: success()
        run: echo "Evaluation passed. Proceeding with deployment."
```

## 3. How it works

When a pull request is opened:

1. GitHub Actions runs `evaluate_rag.py`
2. RAGAS scores faithfulness and answer relevancy against your dataset
3. If either score is below the threshold, `sys.exit(1)` fails the job
4. The PR is blocked from merging until the scores recover
5. If both pass, the deploy step runs

## Adjusting thresholds

Start conservative. A faithfulness threshold of 0.85 is a
reasonable starting point. Lower it if your use case tolerates
more hallucination risk; raise it for high-stakes domains like
legal or medical.
